## Misión 1 - ¿Pasivo, semipasivo o activo?

- **Pasivo (P):** consultamos información de otras fuentes sin enviar nada directamente al objetivo
- **Semipasivo (S):** visitamos recursos públicos del objetivo, como lo haría un visitante normal
- **Activo (A):** interactuamos directamente con el objetivo de forma más visible o distinguible

| Nº | Acción | Tipo | ¿Por qué? |
|---|---|---|---|
| 1 | Buscar en Google `site:megacorpone.com` | **P** | La búsqueda se hace en Google, sin consultar directamente a la empresa |
| 2 | Abrir `megacorpone.com/about.html` | **S** | Visitamos una página pública como cualquier usuario |
| 3 | Consultar el WHOIS del dominio | **P** | Preguntamos a los registros del dominio, no al servidor de la empresa |
| 4 | Consultar una copia antigua en Wayback Machine | **P** | La información sale del archivo histórico de un tercero |
| 5 | Descargar `robots.txt` con curl | **S** | Hacemos una petición normal a un archivo público de la web |
| 6 | Hacer ping a `www.megacorpone.com` | **A** | Enviamos paquetes directamente al objetivo para comprobar si responde |
| 7 | Mirar la IP en `bgp.he.net` | **P** | Consultamos datos públicos de redes en un servicio externo |
| 8 | Llamar a recepción para preguntar por el jefe de IT | **A** | Contactamos directamente con una persona de la empresa |

## Misión 2 - La web por dentro: personas y contacto

Abrimos estas páginas desde Windows:

- https://www.megacorpone.com/about.html
- https://www.megacorpone.com/contact.html

En Kali guardamos las páginas y buscamos los correos publicados

```bash
curl -s -o about.html https://www.megacorpone.com/about.html
curl -s -o contact.html https://www.megacorpone.com/contact.html
grep -Eo '[A-Za-z0-9._-]+@megacorpone\.com' about.html contact.html | cut -d: -f2 | sort -u | tee correos.txt
wc -l correos.txt
```

**Pregunta: ¿Qué formato de correo usa la plantilla?**

El formato se descubre comparando los correos reales de `correos.txt`. Hay que comprobar si siguen una estructura como nombre.apellido, inicial.apellido u otra. **Formato real pendiente de comprobar**, para no inventarlo

**Pregunta: ¿Por qué el correo del CEO es distinto?**

Seguramente porque utiliza una dirección personalizada o una cuenta más antigua. También puede ser para separar su correo del formato del resto de empleados, pero hay que confirmar primero cuál aparece en la página

## Misión 3 - Metaficheros

Buscamos los archivos públicos que pueden dar información sobre rutas y configuración de la página

```bash
curl -s https://www.megacorpone.com/robots.txt | tee robots.txt

for f in sitemap.xml .well-known/security.txt; do
  echo -n "$f -> "
  curl -s -o /dev/null -w '%{http_code}\n' https://www.megacorpone.com/$f
done | tee metaficheros.txt
```

| Archivo | Resultado | Fuente y hora |
|---|---|---|
| `robots.txt` | Ruta concreta pendiente de consultar | `robots.txt` - hora pendiente |
| `sitemap.xml` | Código HTTP pendiente | `metaficheros.txt` - hora pendiente |
| `.well-known/security.txt` | Código HTTP pendiente | `metaficheros.txt` - hora pendiente |

**Pregunta: ¿Qué ruta concreta aparece en robots.txt?**

Hay que copiar exactamente la ruta que salga al ejecutar el primer comando. **Pendiente de comprobar en `robots.txt`**

**Pregunta: ¿Por qué robots.txt no protege nada?**

Porque es un archivo público que cualquiera puede leer. Solo da indicaciones a los buscadores y no impide que alguien entre en esas rutas. Si hay algo privado, hay que protegerlo con permisos y autenticación

**Evidencia:** captura del contenido de `robots.txt` y los códigos HTTP

## Misión 6 - Registros: dominio, IP y red

Consultamos quién registró el dominio, qué IP tiene la web y a qué organización pertenece esa IP

```bash
whois megacorpone.com | tee whois.txt | grep -iE 'registrar:|creation date|expiry date|name server'
dig +short www.megacorpone.com | tail -1 | tee ip.txt
whois $(cat ip.txt) | tee whois_ip.txt | grep -iE 'netrange|cidr|orgname|originas|country'
```

En Windows también abrimos `https://bgp.he.net/ip/LA_IP_OBTENIDA`, sustituyendo el texto por la IP real

El PDF permite consultar RDAP de forma opcional:

```bash
sudo apt install -y rdap
rdap -w megacorpone.com
```

## Misión 7 - Cerrar y sellar las evidencias

Cuando ya tenemos todos los archivos, cerramos la grabación de la terminal y generamos su huella SHA256

```bash
exit
sha256sum *.txt *.html sesion.log > evidencias.sha256
sha256sum -c evidencias.sha256
cd ~
tar czf huella_MCO_$(whoami).tar.gz huella/
```

Es importante ejecutar `exit` para cerrar `script` antes de calcular los hashes

**Pregunta: ¿Qué pasaría si editas correos.txt y repites -c?**

El archivo ya no tendría la misma huella SHA256. Al ejecutar la comprobación aparecería `FAILED` para ese archivo, porque ha cambiado su contenido desde que generamos el hash

**Evidencia:** captura con la comprobación `sha256sum -c` mostrando `OK` y el archivo comprimido creado

## Recomendaciones de seguridad

Después de revisar la información pública, estas son algunas medidas que podrían ayudar a la empresa:

1. Evitar publicar correos personales y datos de trabajadores que no sean necesarios, para reducir intentos de phishing
2. No guardar páginas o archivos privados en rutas públicas y confiar en permisos reales, no en `robots.txt`
3. Mantener actualizado el servidor web para que las versiones antiguas no se conviertan en un problema
4. Revisar qué documentos salen en Google y si contienen información que debería ser privada
5. Comprobar qué información antigua sigue apareciendo en los archivos de Internet
